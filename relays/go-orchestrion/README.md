# Go relay — Datadog Orchestrion (build-time weaving)

Variant `datadog-go-orchestrion`, setup tier **`build-time`**: the naive app
in `main.go` imports no tracing API whatsoever (compare
`relays/go/none/main.go`), and every propagation behaviour is woven in during
compilation by [Orchestrion](https://github.com/DataDog/orchestrion) —
`orchestrion go build` instead of `go build` is the only delta from an
uninstrumented build.

| leg | library | woven? |
|---|---|---|
| http | net/http (server + client) | yes |
| grpc | google.golang.org/grpc | yes |
| kafka | github.com/IBM/sarama | yes — same client + dd-trace-go version as the hand-wired `datadog-go` relay, so the two rows compare manual wiring vs weaving directly |
| rabbitmq | github.com/rabbitmq/amqp091-go | **no** — dd-trace-go has no amqp091 integration; the dark rabbitmq cells measure that |

Integration selection is the pin default: `orchestrion.tool.go` (generated by
`orchestrion pin`) imports `dd-trace-go/orchestrion/all/v2`, and the weaver
only injects for libraries the app imports. Versions are pinned in `go.mod`
(Dependabot bumps them).

Measured result (see `MATRIX.md` on the latest release and FINDINGS §11):
http/grpc → http/grpc legs match the hand-wired relay exactly — W3C baggage
*and* `ot-baggage-*` included — but every Kafka-touching leg starts a **new
trace** (sarama's `SyncProducer.SendMessage` has no context parameter for the
weaver to hold on to, and the woven consumer doesn't continue the trace from
record headers).

Gotchas encoded in the Dockerfile:

- Woven dependencies are invisible to `go version -m` (Orchestrion patches
  the link step behind the go tool's back), so the build **asserts dd-trace-go
  symbols with `go tool nm`** — an un-woven binary fails the image build.
- The tracer version is stamped via `-ldflags -X main.tracerVersion=...` for
  the same reason (`debug.ReadBuildInfo` can't see it).
- `orchestrion pin` prints a spurious "removing unnecessary import …
  replacement directory does not exist" warning against the published
  `all/v2` module; it is cosmetic — the build weaves regardless.
